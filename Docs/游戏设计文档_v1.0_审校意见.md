## 二、P0 阻塞级问题（开工前必须决策）

### P0-1 引擎二选一未定，第五章技术方案整体悬空

- **位置**：文档头 + §5.1。
- **问题**：抬头写 "Unity 2022 LTS / Unreal Engine 5" 二选一未定，但 §5.1 的全部技术选型（C#、ML-Agents、Bolt / NodeGraphProcessor、Mirror）**只在 Unity 下成立**。UE5 下行为树、网络方案、AI 方案全部要重写（Behavior Tree 是引擎内置，网络走 Replication，ML-Agents 不可用）。
- **风险**：若第三阶段才切 UE5，AI 与网络架构推倒重来。
- **建议**：v1.1 直接定案 **Unity 2022 LTS（或更新的 Unity 6 LTS）**。理由：原型期迭代速度、RTS 大量单位的 ECS/DOTS 路径、团队 C# 复用。抬头删掉"/ UE5"，UE5 仅作为"已评估后放弃"的决策记录保留一句。

### P0-2 时间模型自相矛盾：战役是 RTS 实时，却同时存在"回合"和"日"

- **位置**：§2.2（"每日消耗"）、§2.3（技能冷却写"1 回合 / 2 回合"）、§4.1（"第 X 战役/年"）、§3.1（"粮草 < 3 日消耗"）。
- **问题**：战役阶段是实时 RTS，但技能冷却是"回合"，粮草消耗是"日"，元游戏层又是"战役/年"。三套时间单位混用，技能冷却在实时阶段无法落地。
- **建议**：在 v1.1 §2.1 明确双层时间模型：
  - **战略层（庙算）**：回合制，单位为"旬/月"，外交、间谍、谋略点恢复在此结算；
  - **战役层（战场）**：实时，技能冷却用**秒**（如减灶 CD 90s），粮草用**战场计时**（如部队断粮后每 60s 士气 -X），"日消耗"换算为战前补给天数（如带 3 日粮 = 可支撑 18 分钟战场时间）。
- 现有"1 回合/30 谋略点"统一改写为"战略层 CD：1 旬；战场消耗：30 谋略点"这种双轴表述。

### P0-3 兵种克制环"重步 → 枪兵"不成立，且枪兵未进七国矩阵

- **位置**：§2.4。
- **问题**：克制环为 `轻骑 → 弩兵 → 重步 → 枪兵 → 轻骑`。
  1. 常识上**枪兵（长戟/长矛）是反骑兵单位**，箭头应是枪兵 → 轻骑之外，还应当"枪兵克骑兵、弩兵克枪兵、重步克弩兵"之类；文档写"重步克枪兵"缺乏战术依据（重步兵盾阵接近后确实能压制枪兵，但并非经典石头剪刀布关系）。
  2. **七国特色兵种表里没有任何一国的特色兵种是"枪兵"**，克制环出现一个矩阵中不存在的基础类别；"重步"同时对应秦锐士和魏武卒两个特色位，"弩兵"又同时对应韩劲弩和楚巨弩，**类别与特色兵种的映射关系没有定义**（特色兵是基础兵的升级，还是独立兵种？）。
- **建议**：
  1. 克制环改为经典可解释版本：**枪兵/矛阵 → 轻骑 → 弩兵/弓兵 → 重步 → 枪兵**（重步盾甲近战冲垮静止矛阵，枪阵正面拒马克骑，骑兵机动追猎弩手，弩手射程射杀重甲）。
  2. v1.1 增加一张"**基础兵种（4 类）× 七国特色变体**"映射表，明确特色兵种 = 基础兵种的国家级强化版（如魏武卒 = 枪兵系强化，秦锐士 = 重步系强化，韩劲弩 = 弩兵系强化），并说明克制系数（建议克制伤害 ×1.35、被克 ×0.75，先给数值再调）。

### P0-4 多人对战的"欺骗/情报"如何在网络层防作弊——核心卖点零架构

- **位置**：§5.1 仅一句 "Mirror / Photon（支持多人异步对战）"。
- **问题**：本游戏核心是信息不对称。PvP 下欺骗技能（减灶、烽火疑兵）的假单位、假炊烟、假情报如果同步到客户端，**内存修改/封包查看即可识破一切诡计**，核心玩法在联机直接死亡。文档对此零设计；"异步对战"的措辞也与 2–4 人实时 RTS 冲突（异步是回合制概念）。
- **建议**：v1.1 §5 新增"网络架构"小节，原型期就定：
  - **权威服务器（authoritative server）**，服务端持有全部真值；
  - **感知过滤（interest management / fog-of-war culling）**：不在己方感知范围内的敌方真实单位**根本不下发到客户端**，客户端只收到"你方斥候应当看到的东西"（含欺骗技能主动注入的假实体）；
  - 假实体由服务端生成、带正常视野遮挡规则，客户端无法区分；
  - 落锁重连、观战/录像同样走服务端数据流。
- 该决策直接决定网络中间件选型（见 P2-3），必须与 P0-1 同批定。

### P0-5 情报"可信度"是玩法核心，但只有 UI 标签，没有生成模型

- **位置**：§1.2、§4.2 侦查操作（情报标"高/中/低"可信度）。
- **问题**：可信度从哪算？由什么决定？斥候数量？距离？时间衰减？敌方反间等级？文档把信息战当第一卖点，却只给了一个显示标签，没有任何机制定义。玩家也无法理解"我做什么能提高/降低一条情报的可信度"。
- **建议**：v1.1 增加独立的《情报系统》小节（后续可展开为单独模块文档），最小定义：
  - **情报来源**：斥候目视（受距离/数量/时长影响）、降兵/乡民口供（天然低可信）、截获文书（高可信但可被反间伪造）；
  - **可信度 = f(目击单位数, 连续目击时长, 情报年龄衰减, 来源权重, 敌方当前生效的欺骗技能)**，0–100% 连续值，UI 再映射为高/中/低；
  - **双向规则**：玩家对 AI 用计时，AI 走 §3.1 信任度系统；AI 对玩家用计时，同一条公式生成玩家情报面板上的可信度标签。两套规则共用一张数值表，保证公平可解释。

## 三、P1 高优问题（第一阶段内补齐）

### P1-1 信任度算法会被"一致的假情报"稳定骗死

- **位置**：§5.2 `AITrustSystem`。
- **问题**：信任度只由"与上一条情报是否一致"累加，而欺骗技能的设计恰恰是**持续输出一致的假象**（连续几天减灶，炊烟数据彼此完全一致）→ `consistentReports` 一路涨到顶 → AI 必信。这等于鼓励最简单的 spam，与"识破后反击"的设计意图相反。且 0.2 的下限意味着怀疑状态下仍有较高轻信概率。
- **建议**：
  1. 引入**独立信源交叉验证**：信任度增量需要来自不同斥候/不同方向的目击，同一信源重复确认只给极小增量；
  2. **高利害决策强制复核**：当情报将触发"大军压上/放弃粮道"这类高代价行为时，AI 必须先派斥候复核目标区域，复核期间不执行；
  3 一致性权重应随**情报年龄衰减**（3 分钟前的目击不能持续背书）；
  4. 信任度按**对象/通道分桶**（对"赵军西线兵力"一个值，对"秦军后方有无伏兵"另一个值），不要一个全局标量；
  5. 去掉中间态的纯随机 `Random < 0.5`，改为"按当前可信度做概率行动 + 同时派出验证斥候"，避免决策抽风。

### P1-2 目标优先级公式 `成功率 × 紧急度` 会饿死高紧急任务

- **位置**：§5.2 `AIGoalSystem`。
- **问题**：断粮时"夺粮"紧急度极高，但敌阵严密导致成功率极低，乘积靠后 → AI 既不打粮也不撤，逻辑死锁。
- **建议**：改为 `priority = urgency + successRate * weight(urgency)`，或对"不做的代价"显式建模：`priority = 成功收益×成功率 − 失败代价×(1−成功率) − 不行动代价`。饥饿等死的"不行动代价"必须进公式。

### P1-3 ML-Agents 与行为树的分工未定义

- **位置**：§3.1 架构图有"适应模块"，§5.1 写 ML-Agents + 行为树。
- **问题**：没有说明哪个模块学习、学什么、何时训练、运行时是否推理。RTS 完整策略用 RL 训练成本极高且不可控；若仅用行为树，"学习玩家模式"无从谈起。
- **建议**：原型期**不上 ML-Agents**。分层方案：
  - 行为树/效用 AI（GOAP 或 Utility AI）负责所有可解释战术决策；
  - "适应模块"先用**轻量玩家画像**实现：统计玩家近 N 场的侧翼袭击率、欺骗技能使用频率、常用进攻时段，写入参数化行为树的权重（如"侧翼被袭率 > 60% 则粮道护卫权重 +0.3"）；
  - ML-Agents 推迟到第三阶段，仅用于离线微操（阵型接敌）实验，不进决策主链路。

### P1-4 技能归属、携带规则、反制链全部缺失

- **位置**：§2.3。
- **问题**：
  1. "通用 / 阵营 / 幕僚专属 / 君主亲率"四类技能，玩家一局能带几个？幕僚专属与在场幕僚是否绑定？幕僚不在场能否用？
  2. 有"减灶/增灶/烽火疑兵"但**没有反制手段说明**：识破是自动的还是需要"识破"技能/斥候目击？被识破后技能是否提前失效、谋略点是否返还？
  3. "全局仅一次"的焚粮断道与 80 点消耗并存，若谋略点不足是卡资源还是不卡？
- **建议**：v1.1 给出：技能槽位规则（如每战役携带 4 计：1 阵营计 + 2 通用计 + 1 在场幕僚专属计）、反制统一机制（斥候目击到假实体的"破绽条件"即识破，如近距看到灶坑数量与炊烟不符）、识破反馈（对方收到"计被识破"简报、谋略点不返还、该计策进入冷却）。

### P1-5 谋略点经济没有闭环

- **位置**：§2.2 谋略点"每回合自动恢复，或通过情报行为获取"。
- **问题**：恢复速率、上限、双方对称值均未定义；"通过情报行为获取"会与 §3.1 玩家"散布假情报"的行为产生奇怪激励（造假情报还能赚点？）。
- **建议**：给最小经济模型（原型建议：战略层每旬 +20、上限 100；战场层识破敌方一次诡计 +15；成功执行欺骗不产生点数只产生战利）。具体数值进《技能数值表》单独文档。

### P1-6 幕僚"信任度"奖惩把随机战局结果当成建议质量

- **位置**：§3.2。
- **问题**：采纳建议后战败就降信任 → 玩家会觉得幕僚"变胆小/变冒进"是系统在惩罚运气；且性格参数会被信任度双向扭曲（赵括失败后变保守？那他还是赵括吗）。
- **建议**：解耦两件事——
  - **建议质量分（隐藏）**：用"决策时可获得的信息下该建议的期望收益"评估，而非真实战果（运气差不扣分）；
  - **关系值（展示）**：玩家采纳率影响幕僚忠诚度/去留（剧情向），性格参数**终身固定**，不因胜负漂移。
- 另外"变保守/激进"的表现应通过**建议措辞与备选方案数量**体现，而非改变数值模型。

### P1-7 赵骑"忽略地形减速"与"暗度陈仓使步兵穿越不可通行山地"边界冲突

- **位置**：§2.4 赵、§2.3 暗度陈仓。
- **问题**：骑兵"忽略地形减速"是忽略**减益**还是可穿越**不可通行**区域？若后者，暗度陈仓的独特价值被赵国被动永久白嫖。
- **建议**：明确三级地形通行模型——**可通行（平原）/ 减速通行（山林泽）/ 不可通行（绝壁深水）**。赵骑被动只对"减速通行"生效；暗度陈仓临时把一小段"不可通行"变为限时"减速通行"，技能价值即成立。

### P1-8 动态"地图扩展至三晋"是战略层效果，不能做成战场内实时扩地图

- **位置**：§3.3 分支 A。
- **问题**：实时战役中途加载扩展地图，技术与节奏上都是灾难。
- **建议**：该事件效果落在**战略层（元游戏）**：解锁新战役区域、改变下一场可选战场与兵力部署；事件树输出的是"下一幕"而非当前战场的流式扩容。

### P1-9 分支 B 的失败惩罚 +20% 攻击是"失败螺旋"

- **位置**：§3.3。
- **问题**：玩家没杀掉白起（本来就更可能是因为打得不够好），下场白起还变强 20%，弱者愈弱。
- **建议**：惩罚改为**非数值型压力**：白起获得新行为（更主动设伏、主动请求援军），或开启"离间秦廷/暗杀"支线把补救主动权交回玩家；避免直接给敌方数值加成。

| P2-12 | §7.1 | DLC 若含"名将/技能"而本体玩家在多人中遇到，存在 Pay-to-Win 与对战公平争议 | 明确：所有影响对战的单位/技能对**全体多人玩家**可用（拥有者可选用），DLC 只锁战役剧本、叙事内容与外观；类似《帝国时代 II》文明策略需重新评估 |

## 五、关键内容缺口（v1.1 应新增的章节/文档）

以下内容在 v1.0 中完全缺失，但其机制已经被正文引用，建议至少在 v1.1 立章、再逐个展开为模块文档：

1. **情报与可信度系统**（P0-5，最高优先，建议第一份独立模块文档）

3. **饥饿度/补给系统细则**：§2.3 焚粮引用了"饥饿度"但全文无定义
4. **胜利/失败条件**：战役级（歼敌/夺点/烧粮/时限）与战役级（灭国/合纵霸权）均未定义
5. **战略层（元游戏）规则**：七国地图形态、回合结构、城池/疆域、科技或政令树

7. **基础兵种数值表**：生命/攻击/防御/移速/射程/造价/训练时长，七国变体的差值
8. **技能全集规划**：12 个首发计策的名单（目前正文只列 5 个，另提了声东击西、反间、借刀杀人但无词条）
9. **多人模式规则**：人数、资源对称性、欺骗技能在对称局的反制体验、断线/投降
10. **存档与编年史回放的数据结构**（§5.3 提了存储形式但无 schema）

## 六、值得保留的设计优点（修订时勿误伤）

- "信息不对称 + 三十六计"的核心概念差异化明确，是文档最大资产；
- 阵营特色与地形/季节挂钩（赵骑、楚水军、燕冬季加成）有天然的 counter-pick 深度；
- 幕僚性格参数表（五维）是很好的建议系统底座，方向正确，只改反馈机制（P1-6）；
- 第八章用真实推演日志回溯 AI 信任度变化的做法极好，建议形成惯例——**每条 AI 决策都带可复盘的因果链日志**，这既是调试工具也是卖点（战后"敌方视角复盘"）；
- 垂直切片选赵秦 + 滏口陉，聚焦合理。
